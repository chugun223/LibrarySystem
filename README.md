Library System

Для выполнения практической работы №4 были созданы три новые сущности: 
Author - описывает автора книги
Genre - описывает жанр книги
Loan - описывает факт выдачи книги пользователю

Связи между сущностями следующие: 
1. У одной книги один автор и один жанр, поэтому Book ссылается на Author и Genre через ManyToOne.
2. У одного автора много книг, у одного жанра много книг — это обратные OneToMany связи со стороны Author и Genre.
3. У одного пользователя может быть много выдач, у одной книги много выдач, поэтому Loan ссылается на User и Book через ManyToOne, а User и Book имеют обратные OneToMany связи на Loan.

Для каждой новой сущности, а также для старых сущностей User и Book были созданы репозитории на основе CrudRepository: 
UserRepository
BookRepository
AuthorRepository
GenreRepository
LoanRepository

В часть репозиториев были добавлены кастомные методы с использованием наименовани методов Query Lookup Strategies и методы с запросом на языке JPQL с аннотацией @query.

Для BookRepository был создан аналог на Criteria API. Он реализован в виде отдельного интерфейса BookRepositoryCustom и класса BookRepositoryCustomImpl.

Так как по заданию требовалось отключить консольный ввод, все файлы, связанные с консолью, не были удалены, а были закомментированы.

Для всех репозиториев с кастомными методами и для Criteria API были написаны тесты. Также были написаны тесты для сервиса.

В качестве СУБД используется PostgreSQL. Для запуска используется Docker, все параметры подключения и запуска БД прописаны в файле docker-compose.yaml. Параметры подключения приложения к БД прописаны в application.yaml, при этом сами значения подставляются из переменных окружения. переменные окружения хранятся в файле .env Он не коммитится в репозиторий. Для примера в репозитории хранится файл .env.example, в котором указаны все необходимые переменные и значения по умолчанию.

Миграции базы данных настраиваются с помощью Liquibase. Все необходимые файлы миграций хранятся в папке src/main/resources/liquibase. Там находится master-changelog.xml, который подключает остальные файлы: create-authors.xml, create-genres.xml, create-users.xml, create-books.xml и create-loans.xml. Каждый файл создаёт соответствующую таблицу.

Схема базы данных была спроектирована с помощью сервиса dbdiagram. Изображение схемы хранится в папке documents. На диаграмме отражены все пять сущностей, типы данных, первичные ключи, внешние ключи и связи между таблицами.

Для запуска приложения сначала нужно создать файл .env. Его можно скопировать из .env.example 
После этого нужно выполнить в консоли команду:
docker-compose up -d
которая поднимет контейнер с PostgreSQL. Затем можно запустить само приложение. Однако по заданию консольный ввод был отключён, поэтому взаимодействовать с приложением через консоль нельзя. 
Вместо этого можно запустить тесты, которые проверяют работу репозиториев и транзакционного сервиса.
